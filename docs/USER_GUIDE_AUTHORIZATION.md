# دليل إدارة التصاريح - منصة اختبار الاختراق

## نظرة عامة

نظام إدارة التصاريح هو المكون الأساسي الذي يضمن الاستخدام القانوني والأخلاقي للمنصة. يجب الحصول على تصريح كتابي صريح قبل إجراء أي عملية اختبار اختراق.

## ⚠️ الأهمية القانونية

**تحذير حاسم:** إجراء اختبار اختراق بدون تصريح كتابي صريح يعتبر:
- جريمة جنائية في معظم الدول
- انتهاكاً لقوانين الوصول غير المصرح به للأنظمة
- سبباً للمساءلة القانونية والمدنية

**لا تتجاوز هذه الخطوة أبداً!**

## مفاهيم أساسية

### ما هو التصريح؟

التصريح هو وثيقة قانونية موقعة تمنح الإذن الصريح لإجراء اختبارات اختراق على أنظمة محددة. يجب أن يتضمن:

1. **معلومات المنظمة:** اسم الشركة أو المنظمة المالكة للأنظمة
2. **نطاق العمل (Scope):** الأنظمة والشبكات المصرح باختبارها بالتحديد
3. **الفترة الزمنية:** تاريخ البدء والانتهاء للتصريح
4. **أنواع الاختبارات:** العمليات المسموح بإجرائها
5. **التوقيع:** توقيع من شخص مخول قانونياً

### نطاق العمل (Scope)

نطاق العمل يحدد بدقة ما يمكن وما لا يمكن اختباره:

- **داخل النطاق (In-Scope):** الأنظمة المصرح باختبارها
- **خارج النطاق (Out-of-Scope):** الأنظمة الممنوع اختبارها

**مهم جداً:** أي نظام غير مذكور صراحة في نطاق العمل يعتبر خارج النطاق.

## إنشاء تصريح جديد

### الخطوة 1: الوصول إلى صفحة التصاريح

1. سجل الدخول إلى المنصة
2. انتقل إلى **التصاريح** من القائمة الرئيسية
3. اضغط على **+ تصريح جديد**

### الخطوة 2: معلومات المنظمة

املأ المعلومات الأساسية:

```
اسم المنظمة: شركة التكنولوجيا المتقدمة
نوع المنظمة: شركة خاصة
الدولة: المملكة العربية السعودية
```

### الخطوة 3: الفترة الزمنية

حدد فترة صلاحية التصريح:

```
تاريخ البدء: 2024-02-01 00:00:00
تاريخ الانتهاء: 2024-02-28 23:59:59
```

**ملاحظات:**
- لا يمكن بدء عمليات قبل تاريخ البدء
- سيتم إيقاف جميع العمليات تلقائياً عند تاريخ الانتهاء
- يُنصح بإضافة هامش أمان (buffer) في التواريخ

### الخطوة 4: تحديد نطاق العمل

#### 4.1 النطاقات (Domains)

أضف النطاقات المصرح باختبارها:

```
example.com
test.example.com
staging.example.com
*.dev.example.com
```

**تنسيقات مدعومة:**
- نطاق محدد: `example.com`
- نطاق فرعي: `test.example.com`
- نطاق فرعي بحرف بدل: `*.dev.example.com`

**تحذير:** استخدم أحرف البدل بحذر شديد!

#### 4.2 نطاقات IP

أضف نطاقات IP المصرح بها:

```
192.168.1.0/24
10.0.0.0/16
172.16.50.100
```

**تنسيقات مدعومة:**
- CIDR notation: `192.168.1.0/24`
- عنوان IP واحد: `172.16.50.100`
- نطاق IP: `192.168.1.1-192.168.1.254`

#### 4.3 الشبكات اللاسلكية

أضف الشبكات اللاسلكية المصرح باختبارها:

```
SSID: CompanyWiFi
BSSID: AA:BB:CC:DD:EE:FF

SSID: GuestNetwork
BSSID: 11:22:33:44:55:66
```

**معلومات مطلوبة:**
- **SSID:** اسم الشبكة اللاسلكية
- **BSSID:** عنوان MAC لنقطة الوصول

**كيفية الحصول على BSSID:**
```bash
# على Linux/Mac
sudo iwlist wlan0 scan | grep -E "ESSID|Address"

# على Windows
netsh wlan show networks mode=bssid
```

#### 4.4 نطاقات البريد الإلكتروني

أضف نطاقات البريد الإلكتروني لحملات التصيد:

```
@company.com
@subsidiary.company.com
```

**ملاحظات:**
- استخدم `@` قبل النطاق
- يمكن تحديد نطاقات فرعية
- سيتم رفض أي بريد إلكتروني خارج هذه النطاقات

### الخطوة 5: أنواع العمليات المصرح بها

حدد أنواع الاختبارات المسموح بها:

#### فحص تطبيقات الويب
```
☑ فحص ثغرات تطبيقات الويب
  ☑ SQL Injection
  ☑ Cross-Site Scripting (XSS)
  ☑ CSRF
  ☑ Directory Traversal
  ☑ Command Injection
  ☐ Denial of Service (DoS) - غير مُنصح به
```

#### حملات التصيد الاحتيالي
```
☑ حملات التصيد الاحتيالي التدريبية
  ☑ رسائل البريد الإلكتروني
  ☑ صفحات الهبوط
  ☑ تتبع التفاعلات
```

#### اختبار الشبكات اللاسلكية
```
☑ اختبار الشبكات اللاسلكية
  ☑ اكتشاف نقاط الوصول
  ☑ اختبار قوة كلمات المرور
  ☑ تحليل حركة المرور
  ☐ هجمات Deauthentication - تتطلب موافقة خاصة
```

### الخطوة 6: معلومات التوقيع

أدخل معلومات الشخص المخول بالتوقيع:

```
الاسم الكامل: أحمد محمد العلي
المنصب: مدير أمن المعلومات (CISO)
البريد الإلكتروني: ahmed.ali@company.com
رقم الهاتف: +966-50-123-4567
```

**متطلبات التوقيع:**
- يجب أن يكون الموقع مخولاً قانونياً
- يُفضل أن يكون في منصب إداري عالي (CTO, CISO, CEO)
- يجب التحقق من صلاحيات التوقيع

### الخطوة 7: تحميل الوثيقة

قم بتحميل نسخة رقمية موقعة من التصريح:

**متطلبات الملف:**
- **التنسيق:** PDF فقط
- **الحجم الأقصى:** 10 MB
- **المحتوى:** يجب أن يتضمن جميع المعلومات المذكورة أعلاه
- **التوقيع:** يجب أن يكون موقعاً رقمياً أو ممسوحاً ضوئياً

**خطوات التحميل:**
1. اضغط على **اختيار ملف**
2. حدد ملف PDF الموقع
3. انتظر حتى يكتمل التحميل
4. تحقق من معاينة الملف

### الخطوة 8: المراجعة والتأكيد

راجع جميع المعلومات بعناية:

```
✓ معلومات المنظمة صحيحة
✓ الفترة الزمنية مناسبة
✓ نطاق العمل محدد بدقة
✓ أنواع العمليات واضحة
✓ معلومات التوقيع كاملة
✓ الوثيقة محملة ومراجعة
```

اضغط على **إنشاء التصريح** للحفظ.

## إدارة التصاريح الموجودة

### عرض جميع التصاريح

انتقل إلى **التصاريح** > **قائمة التصاريح** لعرض:

- **التصاريح النشطة:** صالحة حالياً
- **التصاريح المنتهية:** انتهت صلاحيتها
- **التصاريح الملغاة:** تم إلغاؤها يدوياً
- **التصاريح المستقبلية:** لم تبدأ بعد

### عرض تفاصيل تصريح

اضغط على أي تصريح لعرض:

1. **المعلومات الأساسية:**
   - اسم المنظمة
   - الفترة الزمنية
   - الحالة (نشط/منتهي/ملغى)

2. **نطاق العمل:**
   - النطاقات المصرح بها
   - نطاقات IP
   - الشبكات اللاسلكية
   - نطاقات البريد الإلكتروني

3. **العمليات المرتبطة:**
   - عمليات الفحص المنفذة
   - حملات التصيد
   - اختبارات الشبكات

4. **سجل التدقيق:**
   - تاريخ الإنشاء
   - التعديلات
   - الاستخدامات

### تحديث تصريح

يمكن تحديث بعض المعلومات فقط:

**يمكن تحديثه:**
- تاريخ الانتهاء (تمديد فقط)
- إضافة نطاقات جديدة
- إضافة أنواع عمليات جديدة

**لا يمكن تحديثه:**
- اسم المنظمة
- تاريخ البدء
- إزالة نطاقات موجودة
- الوثيقة الأصلية

**لتحديث تصريح:**
1. افتح التصريح
2. اضغط على **تحديث**
3. قم بالتعديلات المطلوبة
4. حمّل وثيقة تصريح محدثة موقعة
5. اضغط على **حفظ التحديثات**

### إلغاء تصريح

قد تحتاج لإلغاء تصريح في الحالات التالية:
- انتهاء المشروع مبكراً
- طلب من العميل
- اكتشاف مشكلة قانونية
- تغيير في نطاق العمل

**خطوات الإلغاء:**
1. افتح التصريح
2. اضغط على **إلغاء التصريح**
3. أدخل سبب الإلغاء (مطلوب)
4. أكد الإلغاء

**تأثير الإلغاء:**
- ⚠️ سيتم إيقاف جميع العمليات الجارية فوراً
- ⚠️ لن يمكن بدء عمليات جديدة
- ⚠️ لا يمكن التراجع عن الإلغاء

## التحقق من التصريح

### التحقق اليدوي

قبل بدء أي عملية، يمكنك التحقق من صلاحية التصريح:

1. انتقل إلى **التصاريح** > **التحقق**
2. أدخل معرف التصريح أو اختره من القائمة
3. أدخل الهدف المراد اختباره
4. اضغط على **التحقق**

**النتائج المحتملة:**

✅ **صالح:** التصريح نشط والهدف ضمن النطاق
```
التصريح: AUTH-2024-001
الحالة: نشط
الهدف: example.com
النتيجة: ✅ مصرح به
```

❌ **غير صالح - خارج النطاق:**
```
التصريح: AUTH-2024-001
الحالة: نشط
الهدف: external-site.com
النتيجة: ❌ خارج نطاق العمل
```

❌ **غير صالح - منتهي:**
```
التصريح: AUTH-2024-001
الحالة: منتهي
تاريخ الانتهاء: 2024-01-31
النتيجة: ❌ التصريح منتهي الصلاحية
```

### التحقق التلقائي

المنصة تتحقق تلقائياً من التصريح:

1. **عند بدء العملية:** قبل بدء أي فحص أو اختبار
2. **أثناء التنفيذ:** مراقبة مستمرة للأهداف
3. **عند الانتهاء:** التحقق من الامتثال الكامل

**إجراءات تلقائية:**
- إيقاف العمليات عند انتهاء التصريح
- منع الوصول للأهداف خارج النطاق
- تسجيل جميع محاولات التجاوز
- إرسال تنبيهات للمدققين

## مراقبة انتهاء الصلاحية

### الإشعارات التلقائية

ستتلقى إشعارات قبل انتهاء التصريح:

- **30 يوماً قبل الانتهاء:** تذكير أولي
- **7 أيام قبل الانتهاء:** تحذير
- **24 ساعة قبل الانتهاء:** تنبيه عاجل
- **عند الانتهاء:** إشعار بالإيقاف

### تجديد التصريح

لتجديد تصريح منتهي:

1. **لا يمكن تجديد تصريح منتهي مباشرة**
2. يجب إنشاء تصريح جديد
3. حمّل وثيقة تصريح جديدة موقعة
4. حدد نطاق العمل من جديد

**نصيحة:** خطط للتجديد قبل انتهاء الصلاحية بأسبوعين على الأقل.

## أفضل الممارسات

### 1. الدقة في تحديد النطاق

```
✅ جيد:
- example.com
- test.example.com
- 192.168.1.0/24

❌ سيء:
- *.com (واسع جداً)
- 0.0.0.0/0 (جميع الإنترنت!)
- "كل شيء" (غير محدد)
```

### 2. التوثيق الشامل

احتفظ بنسخ من:
- الوثيقة الموقعة الأصلية
- المراسلات البريدية
- محاضر الاجتماعات
- أي تعديلات أو ملاحق

### 3. التواصل المستمر

- أبلغ العميل قبل بدء الاختبار
- أرسل تحديثات دورية
- أبلغ فوراً عن أي مشاكل
- أكد الانتهاء كتابياً

### 4. الامتثال الصارم

```
✅ افعل:
- التزم بنطاق العمل بدقة
- توقف فوراً عند انتهاء التصريح
- سجل جميع الأنشطة
- احترم قيود الوقت

❌ لا تفعل:
- تتجاوز نطاق العمل "قليلاً"
- تستمر بعد انتهاء التصريح
- تختبر أنظمة غير مصرح بها
- تفترض الموافقة الضمنية
```

### 5. الأمان والخصوصية

- احفظ وثائق التصريح في مكان آمن
- لا تشارك التصاريح مع أطراف غير مصرح لها
- استخدم التشفير لتخزين الوثائق
- احذف التصاريح المنتهية بشكل آمن

## استكشاف الأخطاء

### "التصريح غير صالح"

**الأسباب المحتملة:**
1. التصريح منتهي الصلاحية
2. الهدف خارج نطاق العمل
3. نوع العملية غير مصرح به
4. التصريح ملغى

**الحلول:**
```bash
# التحقق من حالة التصريح
npm run cli auth:validate --auth-id <id>

# عرض تفاصيل التصريح
npm run cli auth:show --auth-id <id>

# التحقق من نطاق العمل
npm run cli auth:check-scope --auth-id <id> --target <target>
```

### "الهدف خارج النطاق"

**التحقق:**
1. راجع نطاق العمل في التصريح
2. تأكد من كتابة الهدف بشكل صحيح
3. تحقق من عدم وجود أخطاء إملائية

**مثال:**
```
المصرح به: example.com
المحاولة: www.example.com ❌
الصحيح: example.com ✅

أو أضف www.example.com للنطاق
```

### "العملية غير مصرح بها"

**التحقق:**
1. راجع أنواع العمليات المصرح بها
2. تأكد من اختيار التصريح الصحيح
3. قد تحتاج لتحديث التصريح

## واجهة برمجة التطبيقات (API)

### إنشاء تصريح

```bash
POST /api/v1/authorizations
Content-Type: application/json
Authorization: Bearer <token>

{
  "organizationName": "شركة التكنولوجيا",
  "validFrom": "2024-02-01T00:00:00Z",
  "validUntil": "2024-02-28T23:59:59Z",
  "signedBy": "أحمد العلي",
  "scope": {
    "domains": ["example.com", "test.example.com"],
    "ipRanges": ["192.168.1.0/24"],
    "networks": [
      {"ssid": "CompanyWiFi", "bssid": "AA:BB:CC:DD:EE:FF"}
    ],
    "emailDomains": ["@company.com"]
  },
  "allowedOperations": ["WEB_SCAN", "PHISHING_CAMPAIGN"]
}
```

### التحقق من التصريح

```bash
POST /api/v1/authorizations/:id/validate
Content-Type: application/json
Authorization: Bearer <token>

{
  "target": "example.com",
  "operationType": "WEB_SCAN"
}
```

### إلغاء تصريح

```bash
POST /api/v1/authorizations/:id/revoke
Content-Type: application/json
Authorization: Bearer <token>

{
  "reason": "انتهاء المشروع مبكراً"
}
```

## الامتثال والتدقيق

### سجلات التدقيق

جميع العمليات المتعلقة بالتصاريح مسجلة:

- إنشاء تصريح جديد
- تحديث تصريح
- إلغاء تصريح
- محاولات التحقق
- محاولات التجاوز

**عرض السجلات:**
```bash
# سجلات تصريح محدد
npm run cli audit:auth --auth-id <id>

# جميع سجلات التصاريح
npm run cli audit:auth --all

# تصدير السجلات
npm run cli audit:export --type authorization --format pdf
```

### تقارير الامتثال

يمكن توليد تقارير امتثال شاملة:

```bash
# تقرير امتثال شهري
npm run cli compliance:report --month 2024-02

# تقرير امتثال لتصريح محدد
npm run cli compliance:report --auth-id <id>
```

**محتوى التقرير:**
- جميع التصاريح المستخدمة
- العمليات المنفذة
- الامتثال لنطاق العمل
- أي محاولات تجاوز
- توصيات التحسين

1. ✅ احصل على تصريح كتابي قبل أي اختبار
2. ✅ حدد نطاق العمل بدقة
3. ✅ التزم بالنطاق المصرح به فقط
4. ✅ راقب انتهاء الصلاحية
