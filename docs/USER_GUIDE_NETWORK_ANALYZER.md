# دليل تحليل الشبكات اللاسلكية

## نظرة عامة

محلل الشبكات اللاسلكية هو أداة متقدمة لاختبار أمان الشبكات اللاسلكية (Wi-Fi). يدعم المحلل مجموعة واسعة من الاختبارات لتقييم قوة التشفير واكتشاف الثغرات الأمنية.

## ⚠️ تحذير قانوني حاسم

**تحذير شديد الأهمية:** اختبار شبكة لاسلكية بدون تصريح كتابي صريح من مالك الشبكة يعتبر:
- جريمة جنائية خطيرة (اختراق أنظمة)
- انتهاكاً لقوانين الاتصالات
- سبباً للمساءلة الجنائية والمدنية
- قد يؤدي للسجن والغرامات الكبيرة

**لا تختبر أي شبكة لا تملكها أو لا تملك تصريحاً كتابياً لاختبارها!**

## المتطلبات التقنية

### الأجهزة المطلوبة

```
✓ بطاقة شبكة لاسلكية تدعم وضع المراقبة (Monitor Mode)
✓ بطاقة شبكة تدعم حقن الحزم (Packet Injection)
```

**بطاقات مُنصح بها:**
- Alfa AWUS036NHA
- TP-Link TL-WN722N v1

```

## أنواع الاختبارات المدعومة

### 1. اكتشاف نقاط الوصول
فحص جميع نقاط الوصول اللاسلكية المتاحة.

**المعلومات المجمعة:**
- SSID (اسم الشبكة)
- BSSID (عنوان MAC)
- القناة
- نوع التشفير
- قوة الإشارة
- الشركة المصنعة

### 2. اختبار WEP
اختبار قوة تشفير WEP (قديم وضعيف).

**الخطورة:** حرجة
**الوقت المقدر:** 5-30 دقيقة

### 3. التقاط WPA/WPA2 Handshake
التقاط مصافحة WPA لاختبار قوة كلمة المرور.

**الخطورة:** عالية
**الوقت المقدر:** 1-60 دقيقة (حسب النشاط)

### 4. هجوم WPS
استغلال ثغرات في WPS (Wi-Fi Protected Setup).

**الخطورة:** عالية
**الوقت المقدر:** 2-10 ساعات

### 5. Evil Twin (التوأم الشرير)
إنشاء نقطة وصول مزيفة لاختبار وعي المستخدمين.

**الخطورة:** عالية
**التأثير:** اختبار الوعي الأمني

### 6. هجوم Deauthentication
قطع اتصال الأجهزة لاختبار المرونة.

**الخطورة:** متوسطة
**التأثير:** انقطاع مؤقت للخدمة

### 7. تحليل حركة المرور
مراقبة وتحليل حركة المرور على الشبكة.

**الخطورة:** متوسطة
**المعلومات:** البروتوكولات، الأجهزة، الأنماط

## بدء اختبار شبكة

### الخطوة 1: اختيار الهدف

من قائمة نقاط الوصول المكتشفة، اختر الشبكة المراد اختبارها:

```
الشبكة المستهدفة: CompanyWiFi
BSSID: AA:BB:CC:DD:EE:FF
التصريح: AUTH-2024-001
```

**تحقق من:**
- ✓ الشبكة ضمن نطاق التصريح
- ✓ التصريح صالح
- ✓ نوع الاختبار مصرح به

### الخطوة 2: اختيار الاختبارات

```

☑ WPS Attack

☐ Deauth Attack (يتطلب موافقة خاصة)

### الثغرات المكتشفة

#### 1. كلمة مرور ضعيفة - حرج

```
النوع: كلمة مرور ضعيفة
الخطورة: حرجة
CVSS: 9.8

الوصف:
تم اختراق كلمة مرور الشبكة باستخدام قاموس كلمات المرور 
الشائعة. كلمة المرور المستخدمة: "company123"

التأثير:
- وصول غير مصرح به للشبكة
- إمكانية اعتراض حركة المرور
- خطر سرقة البيانات الحساسة

التوصيات:
1. غيّر كلمة المرور فوراً
2. استخدم كلمة مرور قوية (12+ حرف، أحرف كبيرة وصغيرة، أرقام، رموز)
3. فعّل WPA3 إن أمكن
4. راقب الأجهزة المتصلة بانتظام

مثال على كلمة مرور قوية:
Tr0ng#P@ssw0rd!2024
```

#### 2. WPS مفعّل - عالي

```
النوع: WPS مفعّل مع ثغرة Pixie Dust
الخطورة: عالية
CVSS: 8.1

الوصف:
WPS (Wi-Fi Protected Setup) مفعّل ويحتوي على ثغرة Pixie Dust 
التي تسمح باختراق الشبكة في دقائق.

التأثير:
- اختراق سريع للشبكة (5-30 دقيقة)
- تجاوز كلمة المرور القوية
- وصول غير مصرح به

التوصيات:
1. عطّل WPS فوراً
2. إذا كان WPS ضرورياً، استخدم WPS PIN فقط (لا PBC)
3. حدّث firmware نقطة الوصول
4. راقب محاولات WPS المشبوهة
```

#### 3. بروتوكولات غير آمنة - متوسط

```
النوع: استخدام بروتوكولات غير مشفرة
الخطورة: متوسطة
CVSS: 5.3

الوصف:
تم اكتشاف استخدام بروتوكولات غير مشفرة على الشبكة:
- HTTP (بدلاً من HTTPS)
- FTP (بدلاً من SFTP)
- Telnet (بدلاً من SSH)

التأثير:
- إمكانية اعتراض بيانات الاعتماد
- تسريب معلومات حساسة
- هجمات Man-in-the-Middle

التوصيات:
1. استخدم HTTPS لجميع المواقع
2. استبدل FTP بـ SFTP أو FTPS
3. استبدل Telnet بـ SSH
4. فعّل HSTS على الخوادم
5. استخدم VPN للاتصالات الحساسة
```

## الإشعارات الفورية

عند اكتشاف ثغرة خطيرة، يتم إرسال إشعار فوري لمالك الشبكة:

```
الموضوع: تنبيه أمني عاجل - ثغرة حرجة في شبكة CompanyWiFi

مرحباً،

تم اكتشاف ثغرة أمنية حرجة في شبكتك اللاسلكية CompanyWiFi 
أثناء اختبار الأمان المصرح به.

الثغرة: كلمة مرور ضعيفة
الخطورة: حرجة
التأثير: إمكانية الوصول غير المصرح به للشبكة

الإجراء المطلوب فوراً:
1. غيّر كلمة مرور الشبكة
2. راجع الأجهزة المتصلة
3. راجع سجلات نقطة الوصول

للتفاصيل الكاملة، راجع التقرير المرفق.

مع تحياتنا،
فريق الأمن السيبراني
```

## توليد التقارير

### أنواع التقارير

#### 1. تقرير فني مفصل
```
- جميع الثغرات المكتشفة
- تفاصيل الاختبارات
- الأدلة الفنية
- خطوات إعادة الإنتاج
- توصيات الإصلاح المفصلة
```

#### 2. ملخص تنفيذي
```
- نظرة عامة عالية المستوى
- أهم الثغرات
- مستوى المخاطر الإجمالي
- التوصيات الاستراتيجية
```

#### 3. تقرير الامتثال
```
- معايير الأمان (ISO 27001، PCI DSS)
- الثغرات المؤثرة على الامتثال
- خطة الإصلاح
- الجدول الزمني
```

### توليد التقرير

```bash
# تقرير PDF
npm run cli network:report \
  --session-id <session-id> \
  --type technical \
  --format pdf \
  --output network-report.pdf

# تقرير HTML
npm run cli network:report \
  --session-id <session-id> \
  --type executive \
  --format html \
  --output network-report.html
```

## حذف البيانات الحساسة

```
✓ كلمات المرور المكتشفة: محذوفة
✓ حزم الشبكة الملتقطة: محذوفة
✓ عناوين MAC للأجهزة: مجزأة (hashed)
✓ عناوين IP: محذوفة
✓ الإحصائيات: محفوظة (مجهولة)
```

## أفضل الممارسات

### 1. قبل الاختبار

```
✅ افعل:
- احصل على تصريح كتابي من مالك الشبكة
- أبلغ فريق تقنية المعلومات
- اختر وقتاً مناسباً (خارج ساعات العمل)
- احتفظ بنسخة احتياطية من إعدادات الشبكة

❌ لا تفعل:
- تختبر شبكة لا تملكها
- تختبر خلال ساعات العمل الحرجة
- تستخدم هجمات عدوانية جداً
- تتجاهل تحذيرات النظام
```

### 2. أثناء الاختبار

```
✅ افعل:
- راقب تأثير الاختبار على الشبكة
- توقف فوراً إذا ظهرت مشاكل
- وثق جميع الخطوات
- احترم خصوصية المستخدمين

❌ لا تفعل:
- تترك الاختبار دون مراقبة
- تستمر إذا كانت الشبكة تتأثر سلباً
- تستخدم البيانات المجمعة لأغراض أخرى
- تشارك النتائج مع أطراف غير مصرح لها
```

### 3. بعد الاختبار

```
✅ افعل:
- أبلغ مالك الشبكة فوراً بالثغرات الحرجة
- قدم توصيات واضحة للإصلاح
- احذف جميع البيانات الحساسة
- تابع تنفيذ الإصلاحات

❌ لا تفعل:
- تؤخر الإبلاغ عن الثغرات الحرجة
- تحتفظ بكلمات المرور المكتشفة
- تشارك النتائج علناً
- تستخدم الثغرات لأغراض غير مصرح بها
```

## استكشاف الأخطاء

### "البطاقة لا تدعم وضع المراقبة"

**الحل:**
```bash
# التحقق من التعريفات
lsusb
lsmod | grep 80211

# تثبيت التعريفات المناسبة
sudo apt-get install firmware-atheros
```

### "فشل التقاط المصافحة"

**الأسباب:**
- لا يوجد نشاط على الشبكة
- الإشارة ضعيفة
- التداخل مع شبكات أخرى

**الحلول:**
```bash
# تحسين الإشارة
sudo iwconfig wlan0 txpower 20

# تغيير القناة
sudo iwconfig wlan0 channel 6

# زيادة مدة الانتظار
npm run cli network:test \
  --target CompanyWiFi \
  --timeout 3600
```

### "WPS Attack فشل"

**الأسباب:**
- WPS معطّل
- نقطة الوصول محمية ضد Pixie Dust
- تم تفعيل Rate Limiting

**الحلول:**
- تحقق من تفعيل WPS
- جرب طريقة هجوم مختلفة
- انتظر وأعد المحاولة لاحقاً
